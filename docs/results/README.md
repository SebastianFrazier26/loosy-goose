## What is stale, and how stale

These files are kept verbatim, as the record of what a given run said. Nothing here is edited to
match the code; the notes below are the correction.

**Only `exp_a_summary.txt` and `exp_b_summary.txt` are stale.** They were not re-run by the final
grid. They report Phase 1 results whose conclusions are relative — stability against a
pre-registered threshold, methods against each other at one budget — so the extractor changes since
do not overturn them. Their absolute `atom_recall` figures were measured under `ATOMS_VERSION` 1
and should not be quoted as levels.

**Older tables that are no longer here.** The final grid overwrote each file under its own name,
by decision (see [PHASE2.md](../PHASE2.md), "Decided 2026-10-02, after the final grid"). Earlier
versions are in git history:

- The 14-arm Experiment F table (exact, one-pass and stochastic greedy arms included, run
  2026-09-22 to 28) is at commit 2b98bd2: `git show 2b98bd2:docs/results/exp_f_summary.txt`.
  Ten of those arms were cut on 2026-09-29, so the current file has four.
- `exp_d_band_recheck_summary.txt`, the 2026-09-29 partial grid that re-ran
  `supersede+band+leverage` at `TRANSFORMS_VERSION` 4, is removed; the full exp_d table now covers
  it. It is at commit 9c971fd: `git show 9c971fd:docs/results/exp_d_band_recheck_summary.txt`.
  Dated decisions in `PHASE2.md` that cite it still read correctly against that copy.

**`corpus_stats.txt` — its `atoms` column is atom mentions.** The column is
`sum(len(s.atoms) for s in segments)`: every occurrence counted. It is not the
per-transcript-sum convention `docs/PHASE1.md` and `docs/PHASE2.md` use, and it is not the global
distinct union either. Three conventions are in use across this project; see the counting note in
[../PHASE1.md](../PHASE1.md). Do not compute a share by putting one of them over another.
Regenerate with `uv run python experiments/corpus_stats.py`, which reads `data/local/` as well as
the public corpora.

**`exp_c_summary.txt` — two transcripts print "too few code segments", by design.** In C3,
`trace-commons_11ef2190` and `trace-commons_4c09dfa9` carry too few code segments for the
embedder comparison, and `trace-commons_4c09dfa9` prints the same line in C1. That is the
script's minimum-size guard, not a failure.

**Cost columns use two conventions.** The exp_f, exp_g and exp_h cost blocks take each
transcript's median over its ratios, then the median over transcripts (`supersede+leverage` reads
0.32 s per 100k tokens). Experiment E's E4 takes the median over all sweep points
(`supersede+leverage` reads 0.38). Compare costs within one table, not across them.

## Privacy

Rows labelled `local_5k` … `local_200k` come from the author's own Claude Code sessions, which
contain unrelated employer work. Those transcripts are gitignored and never committed. Only
aggregate numbers appear here — the experiment scripts already withhold sample topics and
direction labels for local rows (`(local session: withheld)`, `(private)`), and the session
UUIDs that appeared in the original filenames have been stripped from these copies.

Reproducing on another machine gives you the public rows immediately via `fetch_public.py`;
local rows regenerate from whatever sessions that machine has, via `pick_local.py`.

- 2026-09-09 — `metrics.atom_recall_final`: atom recall against the session's final-state atom set (`apply_supersession(original)`), reported alongside the existing all-history `atom_recall` rather than replacing it — the latter counts atoms from superseded reads/edits that no longer describe anything real, which `atom_recall_final` does not.
- 2026-09-09 — Phase 2 rate-distortion runner (`experiments/exp_d_curves.py`): every method (baselines, Experiment B strategies, Experiment A as labeller, Experiment C stacked supersede/band variants) on one curve per transcript at a shared token budget, checkpointed per transcript. Plots and the cross-method head-to-head are keyed on ACHIEVED compression ratio, not requested keep_ratio, since a supersede-based method's candidate pool can be smaller than its budget (`budget_binding` on each record; per-transcript ceiling surfaced in the summary).
- 2026-09-09 — Experiment E (`experiments/exp_e_analysis.py`): rate-distortion analysis over the Experiment D checkpoints — compression-multiplier elasticity and marginal cost per +1x, per-channel (prose/code/tool_use/tool_result) breakdown at the aggressive operating points, Spearman predictors of how far a transcript can be compressed, and a compute-cost table. Reads checkpoints only, so it re-runs in seconds whenever D is extended.
- 2026-09-09 — `CompressConfig.drop_top`: discard the leading N embedding directions before scoring (Mu & Viswanath All-but-the-Top), targeting the conversational-boilerplate directions Phase 1 observed recurring across unrelated transcripts. Threaded through leverage, ridge and CUR-residual scoring; defaults to 0, so every Phase 1 and Phase 2 number still reproduces and this arrives as a sweep variant rather than a silent change.
- 2026-09-09 — Experiment D checkpoints carry record-level identity (schema 3). Each record now records the `Variant` that produced it, and the file carries a `segments_digest`; a checkpoint is discarded only when the record schema changes or the segmenter's output does. Adding a method, ratio or variant re-runs just its own combinations, replacing the run-level config fingerprint that invalidated all 18 transcripts (~2h) for any grid change. Existing checkpoints were migrated in place after verifying their stored segment counts and token totals still match the current segmenter. First variants swept: `drop_top` 1/2/4 on the four CompressConfig-driven methods.
- 2026-09-09 — atom extraction decodes tool_use payloads before matching (`segment.scannable`). A tool call's segment text is `json.dumps` output, so an edit body's newlines arrive as literal escape sequences: the path pattern read those backslashes as separators and invented atoms (8.7% of the corpus's distinct atoms were escape junk such as the two-character run at the tail of a doubled newline), while a genuine Windows path — doubled by the same serializer — matched nothing at all and was invisible to the metric. Decoding fixes both, rescues identifiers an escape had split, and scans values only, so parameter names (`file_path`, `old_string`, `replace_all`) leave the atom set. Corpus atoms 32,344 to 27,189. `segment.ATOMS_VERSION` is now part of `segments_digest`, so a future extractor change invalidates stored records instead of loading silently beside them.
- 2026-09-09 — `metrics` splits recall into what a side table guarantees and what selection earned: `atom_recall_earned` and `atom_recall_final_earned` score only the atoms no table hands over, `guaranteed_share` reports how much was free, and `compression_ratio` takes `extra_tokens` so a table is charged against output size. Needed before path substitution: emitting a path table would guarantee 28.8% of the final-state atom set outright, lifting `atom_recall` for every method at once and making comparisons before and after incommensurable. With no table the earned columns equal the originals.
- 2026-09-09 — `paths`: path substitution — name each file once in a table, replace every later mention with a short marker, `expand` back. Built and tested but **not yet wired into the pipeline or the sweep**, so nothing currently emits a table. It does three separable things and they are measured separately: the table guarantees the path survives selection, the marker is shorter than the path (3.87% of corpus tokens net of the table's own cost), and scoring stops seeing repetitive path strings. Runs after supersession, which matches `file_path` across tool calls and would otherwise be comparing markers. The marker is numeric rather than the basename because only 52.0% of basenames are unique within a transcript and a basename marker nets 1.93%; `min_mentions` is a knob because 2 is token-optimal and 1 is recall-optimal, which is a real tradeoff rather than a tuning constant.
- 2026-09-09 — corpus surveys (`experiments/survey_paths.py`, `experiments/survey_tool_output.py`): path mass and repetition, and the shape breakdown of `tool_result`. The finding that drives the next shrinker: blocks of 500+ tokens are 11.4% of tool-output blocks but 68.2% of its tokens, and numbered file reads alone are 32.3% of tool-output tokens, of which 99.3% never reach AST banding because the classifier tests lines still carrying their `123→` prefixes. Public transcripts only for any printed sample.
- 2026-09-09 — Experiment D re-run end to end on the corrected atom extractor (18 transcripts, 336 records each; all prior records discarded by the digest, as intended), and the summary table committed to `docs/results/exp_d_summary.txt`. It answers Phase 1's open question with a **split**: spectral beats budget-shaped TF-IDF on atom recall at every rate measured (`ridge` +0.046 to +0.109 all-history; `supersede+band+leverage` +0.043 to +0.111 final-state) and loses to it on semantic coverage at every rate measured (−0.018 to −0.149). The two metrics were chosen to disagree, so which one decides is a design judgement rather than a further measurement, and it is recorded as open. `topics` loses on both, confirming its Phase 1 cut. `drop_top` remains a null post-fix — largest cell +0.004, smallest −0.007.
- 2026-09-09 — `docs/PHASE2.md`: Phase 2 plan — the four path-substitution arms and what each isolates, decisions locked with the option rejected, verified nulls not to re-walk, and the questions still open. `docs/PHASE1.md` records that its reported `atom_recall` figures are inflated by the extractor defect above (conclusions unaffected, being relative; absolute figures should not be quoted), and its "no spectral method beats budget-shaped TF-IDF" line is marked under re-measurement rather than corrected, since the curves that appeared to contradict it were themselves pre-fix.
